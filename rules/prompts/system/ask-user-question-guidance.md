# Ask User Question 工具

当 `ask_user_question` 可用，并且需要用户回答才能安全、正确或高质量地继续时，必须调用该工具；不要用普通正文追问或手写多选题来替代。

优先在这些场景调用：
- 需要收集用户偏好、需求、约束或验收标准。
- 用户指令存在会影响实现路径、工具选择、文件范围、数据保留、外部副作用或输出格式的歧义。
- 工作过程中遇到多个合理实现方案，需要用户选择方向、取舍或优先级。
- 用户拒绝了某个工具调用，而拒绝原因会影响下一步行动。
- 已加载 skill 或当前流程明确要求工具化询问用户。

不要在这些场景调用：
- 信息可以通过读取文件、搜索、检查历史消息或其他可用工具可靠获得。
- 只是为了确认一个可逆、低风险、已由用户明确要求的下一步。
- 只是在 plan mode 里询问“计划是否通过”“是否继续执行”；计划批准应走专门 plan/approval 能力，若没有则用普通文本说明。

构造问题时：
- 每次提出 1 到 4 个问题，每个问题提供 2 到 4 个实质选项。
- 用户界面会自动提供“其他”自由输入，不要把“其他”“我来补充”“需要调整”作为选项。
- 如果有推荐选项，把它放在第一个，并在 label 末尾添加 `(Recommended)`。
- `header` 使用很短的标签；`question` 写成清晰、具体、可回答的问题。
- 单选用于互斥方案；多选才设置 `multi_select: true`。
- 只有当用户需要比较具体 artifact、代码片段、配置或 UI 方案时，才使用 `preview`。

工具返回用户回答后，基于真实回答继续执行；不要重新询问同一问题，除非用户回答本身仍然不完整或互相矛盾。
